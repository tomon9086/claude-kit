# ナレッジ

作業を通じて得た知識・判断基準・パターンを蓄積する。

---

## SKILL.md の書き方

### 基本構成

```markdown
# スキル名

## 概要
このスキルが何をするか、いつ使うかを 1〜2 文で説明する。

## 前提条件
- 必要なツール・環境
- 想定するプロジェクト構成

## 手順
1. ステップ 1
2. ステップ 2
...

## 注意事項
- よくある落とし穴
- やってはいけないこと

## 参考
- 関連リンク・ドキュメント
```

### 良い SKILL.md の特徴

- **具体的**: 「適切に設定する」ではなく「`config.json` の `timeout` を `5000` に設定する」
- **実行可能**: 読んだだけで作業できるレベルの粒度
- **独立性**: 他のスキルに依存しない（依存する場合は明示する）
- **簡潔**: 1 スキル = 1 つの目的。複数の目的があれば分割する

## スキルのカテゴリ分類（暫定）

| カテゴリ | 説明 | 例 |
|----------|------|-----|
| `general` | 汎用。言語・FW 問わず使える | コードレビュー手順、PR 作成 |
| `lang/typescript` | TypeScript 向け | 型定義パターン、ESLint 設定 |
| `lang/python` | Python 向け | 仮想環境構築、型チェック |
| `framework/react` | React 向け | コンポーネント設計 |
| `workflow/ci` | CI/CD 関連 | GitHub Actions の書き方 |
| `workflow/docs` | ドキュメント生成・管理 | README 更新手順 |

## よくある判断基準

### スキルとして切り出すかどうか

以下のいずれかに当てはまれば、スキルとして独立させる価値がある：
- 2 つ以上のプロジェクトで同じ手順を繰り返している
- 手順が複雑で毎回調べ直している
- チームメンバーに説明するときに口頭では伝えにくい

### SKILL.md を更新するタイミング

- 手順が変わったとき（ツールのバージョンアップなど）
- 手順通りに実行してうまくいかなかったとき
- より良いやり方を発見したとき
